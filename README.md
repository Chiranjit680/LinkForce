# LinkForge 2.0 — URL Shortener

A full-stack URL shortener with JWT-secured user accounts, per-user link management, and per-day click analytics. The backend is a Spring Boot 3.4 REST API; a React SPA consumes it.

```
url-shortener-project/
├── url-shortener-sb/        # Spring Boot backend (primary focus of this document)
└── url-shortener-react/     # React + Vite frontend
```

# Backend (`url-shortener-sb`)

## Data model

Schema is generated by Hibernate (`spring.jpa.hibernate.ddl-auto=update`) — there are no migration scripts.

### `users`
| Column | Type | Notes |
|---|---|---|
| `id` | bigint, identity | PK |
| `email` | varchar | |
| `username` | varchar | looked up via `findByUsername` |
| `password` | varchar | BCrypt hash |
| `role` | varchar | defaults to `ROLE_USER` |

### `url_mapping`
| Column | Type | Notes |
|---|---|---|
| `id` | bigint, identity | PK |
| `original_url` | varchar | destination |
| `short_url` | varchar | 8-character slug |
| `click_count` | int | denormalized counter, defaults to 0 |
| `created_date` | timestamp | set at creation |
| `user_id` | bigint | `@ManyToOne` → `users` |

Also holds `@OneToMany(mappedBy = "urlMapping") List<ClickEvent>`.

### `click_event`
| Column | Type | Notes |
|---|---|---|
| `id` | bigint, identity | PK |
| `click_date` | timestamp | one row written per redirect |
| `url_mapping_id` | bigint | `@ManyToOne` → `url_mapping` |

Storing one row per click (rather than only a counter) is what makes the time-series analytics endpoints possible. `click_count` on `url_mapping` is a fast-path duplicate of the same information.

## Authentication & authorization

**Registration** — `UserService.registerUser` BCrypt-encodes the password before saving. `AuthController` hardcodes `ROLE_USER`; the `role` field on `RegisterRequest` is accepted but deliberately ignored, so clients cannot self-assign privileges.

**Login** — `UserService.authenticateUser` delegates to `AuthenticationManager` (backed by `DaoAuthenticationProvider` + `UserDetailsServiceImpl` + `BCryptPasswordEncoder`), then mints a JWT.

**Token** — HS256, signed with a Base64-decoded secret from `JWT_SECRET`:
```
subject : username
roles   : comma-joined authorities, e.g. "ROLE_USER"
iat/exp : issued-at, +172800000 ms (48 hours)
```

**Request flow** — `JwtAuthenticationFilter` runs before `UsernamePasswordAuthenticationFilter`:

```
Authorization: Bearer <token>
   → JwtUtils.getJwtFromHeader
   → JwtUtils.validateToken
   → JwtUtils.getUserNameFromJwtToken
   → UserDetailsService.loadUserByUsername
   → SecurityContextHolder.setAuthentication
```

**Filter chain** (`WebSecurityConfig`) — CSRF disabled, `@EnableMethodSecurity` on:

| Matcher | Rule |
|---|---|
| `OPTIONS /**` | permit all (CORS preflight) |
| `/api/auth/**` | permit all |
| `/api/urls/**` | authenticated, plus `@PreAuthorize("hasRole('USER')")` per method |
| `/{shortUrl}` | permit all |
| anything else | authenticated |

**CORS** (`WebConfig`) — a single allowed origin from `frontend.url`; methods `GET, POST, PUT, DELETE, OPTIONS`; all headers; credentials enabled.

## API reference

Base URL: `http://localhost:8080`

### `POST /api/auth/public/register`
```json
{ "username": "chiranjit", "email": "me@example.com", "password": "secret123" }
```
`200 OK` → `"User registered successfully"` (plain text)

### `POST /api/auth/public/login`
```json
{ "username": "chiranjit", "password": "secret123" }
```
`200 OK`
```json
{ "token": "eyJhbGciOiJIUzI1NiJ9..." }
```

### `POST /api/urls/shorten` 🔒 `ROLE_USER`
```json
{ "originalUrl": "https://example.com/some/very/long/path" }
```
`200 OK`
```json
{
  "id": 12,
  "originalUrl": "https://example.com/some/very/long/path",
  "shortUrl": "QN7XOa0a",
  "clickCount": 0,
  "createdDate": "2026-08-08T14:31:02.11",
  "username": "chiranjit"
}
```
The link is owned by the authenticated `Principal`.

### `GET /api/urls/myurls` 🔒 `ROLE_USER`
Returns `List<UrlMappingDTO>` for the calling user only.

### `GET /api/urls/analytics/{shortUrl}?startDate=&endDate=` 🔒 `ROLE_USER`
Dates are `ISO_LOCAL_DATE_TIME` (`2026-01-01T00:00:00`). Clicks for one link, grouped by calendar day:
```json
[ { "clickDate": "2026-01-14", "count": 7 },
  { "clickDate": "2026-01-15", "count": 3 } ]
```

### `GET /api/urls/totalClicks?startDate=&endDate=` 🔒 `ROLE_USER`
Dates are `ISO_LOCAL_DATE` (`2026-01-01`). Clicks across **all** of the user's links, keyed by day:
```json
{ "2026-01-14": 7, "2026-01-15": 3 }
```
The end date is inclusive — the service queries up to `end.plusDays(1).atStartOfDay()`.

### `GET /{shortUrl}` — public
Looks up the mapping, increments `clickCount`, inserts a `ClickEvent`, and returns `302 Found` with a `Location` header pointing at the original URL. Unknown slug → `404`.

```bash
curl -i http://localhost:8080/QN7XOa0a
```

### Slug generation
`UrlMappingService.generateShortUrl()` builds an 8-character string from a 62-character alphabet (`A–Z a–z 0–9`) using `java.util.Random`.

## Configuration

Every value in `src/main/resources/application.properties` is externalized — the app will not start without these:

| Variable | Example |
|---|---|
| `DATABASE_URL` | `jdbc:postgresql://localhost:5432/urlshortener` |
| `DATABASE_USERNAME` | `postgres` |
| `DATABASE_PASSWORD` | `postgres` |
| `DATABASE_DIALECT` | `org.hibernate.dialect.PostgreSQLDialect` |
| `JWT_SECRET` | Base64-encoded key, ≥ 256 bits for HS256 |
| `FRONTEND_URL` | `http://localhost:5173` |

Fixed settings: `jwt.expiration=172800000` (48 h) and `spring.jpa.hibernate.ddl-auto=update`.

Generate a suitable secret:

```bash
openssl rand -base64 48
```

## Known backend issues

Documented rather than hidden — these are real behaviours of the current code.

1. **Slug collisions are unhandled.** `generateShortUrl()` performs no uniqueness check and there is no unique constraint on `short_url`. A collision silently inserts a duplicate row, after which `findByShortUrl` (which returns a single `UrlMapping`) throws.
2. **Slugs use `java.util.Random`, not `SecureRandom`**, so they are predictable from observed output.
3. **`GET /api/urls/analytics/{shortUrl}` does not check ownership.** It resolves the slug directly, so any authenticated user can read analytics for another user's link. `/myurls` and `/totalClicks` are correctly scoped to the principal.
4. **`JwtUtils.validateToken` throws instead of returning `false`** for expired or malformed tokens; `JwtAuthenticationFilter` swallows it with a blanket `catch (Exception e) { e.printStackTrace(); }`. Requests still fall through as anonymous, but the failure mode is noisy and hides genuine errors.
5. **Malformed date parameters produce a 500**, not a 400 — `LocalDate.parse` / `LocalDateTime.parse` are unguarded.
6. **The redirect path is not `@Transactional`**, so the counter update and the `ClickEvent` insert are not atomic.
7. **`RedirectController` maps `/{shortUrl}` at the root**, which captures every unmatched single-segment path.
8. **Verbose logging is committed** — `org.springframework=DEBUG` and `org.springframework.web.servlet=TRACE` are far too heavy for production.
9. **`getClickEventsByDate` returns `null`** for an unknown slug, which serializes as an empty `200` body rather than a `404`.
10. **Test coverage is a single empty `contextLoads()`.**

# Frontend (`url-shortener-react`)

React 18 + Vite 6 SPA, styled with Tailwind (custom gradients/colors in `tailwind.config.js`) and MUI for modals. Branded **Linklytics** in the UI.

**Key libraries** — `react-router-dom` v7, `react-query` for server state, `axios`, `chart.js` + `react-chartjs-2`, `react-hook-form`, `react-hot-toast`, `dayjs`, `react-copy-to-clipboard`.

**What it does**
- Landing, About, Register, Login, Dashboard, and an error/404 route.
- `PrivateRoute` guards both directions: unauthenticated users are pushed to `/login`, authenticated users are pushed off `/login` and `/register`.
- JWT is held in React Context and mirrored to `localStorage` under `JWT_TOKEN`.
- Dashboard shows a Chart.js bar graph of total clicks per day, a modal for creating a short URL (which auto-copies the result to the clipboard), and a list of links each with copy and an expandable per-link analytics graph.
- Two link formats are supported: `<domain>/s/{slug}` and a subdomain form `url.<domain>/{slug}`. `utils/helper.js` inspects `window.location.hostname` and swaps in `SubDomainRouter` accordingly. Both ultimately hand off to the backend's `GET /{shortUrl}`.

**Environment** (`.env`)

| Variable | Purpose |
|---|---|
| `VITE_BACKEND_URL` | API base URL used by `axios` |
| `VITE_REACT_FRONT_END_URL` | used to build displayed/copied short links |
| `VITE_REACT_SUBDOMAIN` | subdomain-style link base |

```bash
cd url-shortener-react && npm install && npm run dev
```

`public/_redirects` (`/* /index.html 200`) is present for SPA hosting on Netlify.

**Known frontend issues** — `refetch` is threaded into `CreateNewShorten` but the call is commented out, so the dashboard list does not refresh after creating a link; analytics date ranges are hardcoded in `ShortenItem.jsx` and `useQuery.js`; `.env` with a live deployed backend URL is committed.

## Local setup, end to end

1. Start PostgreSQL and create a database.
2. Export the six backend environment variables listed above.
3. `cd url-shortener-sb && ./mvnw spring-boot:run` → API on `:8080`.
4. Point `VITE_BACKEND_URL` at `http://localhost:8080` in `url-shortener-react/.env`.
5. `cd url-shortener-react && npm install && npm run dev` → SPA on `:5173`.
6. Make sure `FRONTEND_URL` matches the SPA origin exactly, or CORS will reject requests.
